# База знаний проекта

Эта область разделяет информацию по **уровню доверия**. Главный принцип ОС:
_предположение не является фактом, пока оно не подтверждено явно_.

## Структура

| Путь | Назначение |
| :--- | :--- |
| `claims.yaml` | Реестр всех утверждений со статусом доверия, источником и владельцем проверки |
| `facts/` | Только подтверждённые данные (`confirmed`), на которые можно опираться в работе |
| `glossary.md` | Единая терминология проекта |

## Уровни доверия (`status`)

| Статус | Значение | Можно ли использовать в работе |
| :--- | :--- | :--- |
| `confirmed` | Проверено, подтверждён источник и владелец | Да |
| `needs-verification` | Требует проверки человеком или ролью | Нет (только как гипотеза) |
| `rejected` | Проверено и отклонено | Нет |

## Жизненный цикл утверждения

```
needs-verification → (проверка) → confirmed
                               ↘ rejected
```

1. Утверждение попадает в `claims.yaml` со статусом `needs-verification`.
2. Ответственная роль или человек проводит проверку по протоколу
   [`templates/fact-verification.md`](../templates/fact-verification.md).
3. Результат фиксируется: статус меняется на `confirmed` или `rejected`,
   заполняются `verified_by` и `verified_at`.
4. Только `confirmed`-утверждения переносятся в `facts/` и используются в
   документах рабочих областей.

## Правила

- Каждое утверждение имеет **уникальный `id`** вида `C-XXX`.
- Каждое утверждение указывает **`source`** — где оно возникло
  (например, `archive/gemini/2_BRAND_DNA.md#section-2`).
- Материалы из `archive/gemini/` по умолчанию имеют статус `needs-verification`.
- Цифры (проценты, цены, сроки) **никогда** не получают статус `confirmed` без
  указания метода проверки в поле `verification_method`.
