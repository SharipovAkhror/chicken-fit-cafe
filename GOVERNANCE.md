# Governance

## Роли управления

| Участник | Полномочия |
| :--- | :--- |
| Владелец проекта | Финальное решение по стратегии, бренду, бюджету, рискам и публикации |
| Системный архитектор | Целостность ОС, источники истины, зависимости, ADR и эскалации |
| Владелец области | Качество и актуальность документов своей области |
| Cross-reviewer | Проверка влияния результата на смежную область |
| AI-роль | Подготовка и проверка артефактов в пределах контракта; не финальное утверждение |

## Модель решений

- Локальные обратимые решения принимает владелец области через PR.
- Межобластные, финансовые, брендовые, архитектурные и необратимые решения
  требуют ADR и утверждения владельца проекта.
- Молчание не считается согласием; решение существует только после фиксации.
- При конфликте источников действует иерархия из `AGENTS.md`.

## Правила ревью

1. Минимум один review от владельца изменённой области.
2. Для межобластного изменения — review каждой затронутой области.
3. Автор не может быть единственным approver критичного решения.
4. AI может дать review и self-check, но человеческое утверждение обязательно
   для областей из раздела «эскалация» в `AGENTS.md`.

## CODEOWNERS

`.github/CODEOWNERS` указывает на `@SharipovAkhror`. После стабилизации процесса
рекомендуется включить защиту ветки `main` (PR + CI + review).

## Изменение самой ОС

Изменения `AGENTS.md`, `GOVERNANCE.md`, ролевых контрактов, валидаторов и схемы
claims требуют:

- issue типа `decision`;
- ADR;
- review системного архитектора;
- утверждения владельца проекта.
