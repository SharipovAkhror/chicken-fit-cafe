# Протокол взаимодействия ролей

## Общий цикл

```
issue → ветка → артефакт → self-check → validate → cross-review → PR → approval → handoff
```

## Правила передачи

1. Передавать можно только артефакт со статусом `approved`, если он служит
   обязательным входом другой роли.
2. Handoff оформляется по шаблону [`../templates/handoff.md`](../templates/handoff.md)
   и прикладывается к PR или issue.
3. Принимающая роль проверяет входные критерии своего контракта до старта.
4. Если вход не готов — создаётся блокирующая задача, работа не начинается.

## Матрица зависимостей входов

| Роль | Ждёт | Обязательный вход |
| :--- | :--- | :--- |
| Бренд-стратег | Архитектор | Подтверждённые факты |
| Визуальный дизайнер | Бренд-стратег | `brand/brand-platform.md` approved |
| Операционный менеджер | Стратегия | Продуктовая матрица approved |
| Финансовый аналитик | Операции | Мощности, штат, цены |
| Продуктовый разработчик | Операции + Дизайн | Service blueprint + design-system approved |

## Разрешение конфликтов

- Конфликт данных → в `knowledge/claims.yaml`, статус блокирующего утверждения
  `needs-verification`, работа приостановлена.
- Конфликт подтверждённых источников → эскалация архитектору и владельцу.
- Спор о границах ролей решается по разделу «Разрешённые пути записи» контрактов.

## Определение готовности handoff

- [ ] Артефакт `approved` с корректными метаданными.
- [ ] Источники и связанные claims указаны.
- [ ] Открытые вопросы и риски перечислены.
- [ ] Принимающая роль подтвердила достаточность входа.
