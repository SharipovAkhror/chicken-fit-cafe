# Безопасность

- В репозитории нет секретов: ни ключей, ни токенов, ни `.env*` (кроме `.env.example`), ни дампов прод-БД, ни персональных данных.
- Клиент использует только publishable key Supabase. Таблицы закрыты RLS; запись — только через RPC с PIN-сессией
  (PIN и токены хранятся в БД только хешем). Публично читаются меню и столы.
- Агент не выполняет необратимые действия (прод-деплой, удаление веток/данных, оплату) без явного согласия владельца.
- Уязвимость: сообщить владельцу `@SharipovAkhror` приватно, не через публичный issue. Скомпрометированный ключ —
  ротировать в Supabase/Vercel, в git не коммитить.
