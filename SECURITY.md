# Безопасность

- **Секретов в репозитории нет**: ни ключей, ни токенов, ни `.env*` (кроме `.env.example`), ни дампов прод-БД, ни персональных данных.
  Имена переменных и где их взять — [`docs/setup.md`](docs/setup.md#переменные-окружения-и-секреты).
- **Ключи.** Клиент использует только publishable key Supabase (публичен по замыслу). Service role key и пароль БД не нужны приложению
  и не хранятся ни в коде, ни в Vercel; пароль БД нужен только человеку/агенту для `psql` и берётся из дашборда Supabase.
- **RLS.** Все таблицы закрыты RLS; анонимно читаются только меню и столы. Запись — только через RPC `security definer`
  (`pos_*`, `report_*`, `rescue_*`) с PIN-сессией; новые функции — с `revoke … from public, anon, authenticated`.
- **PIN и сессии.** PIN хранится только bcrypt-хешем (`staff.pin_hash`, pgcrypto), токен сессии — sha256 (`staff_sessions`);
  неудачные входы ограничиваются по устройству (`login_attempts`). Сид-PIN открыты в миграции 0007 — сменить (issue #4,
  SQL — [`docs/operations.md`](docs/operations.md#смена-pin)).
- **Превью** Vercel закрыты Vercel Authentication; прод-домен публичен.
- Необратимые действия (прод-деплой, откат, запись в прод-БД, удаление веток/данных, оплата) — только с явного согласия владельца.
- Уязвимость: сообщить владельцу `@SharipovAkhror` приватно, не через публичный issue. Скомпрометированный ключ или пароль —
  ротировать в Supabase (API Keys / Database password) и обновить env в Vercel; в git не коммитить.
