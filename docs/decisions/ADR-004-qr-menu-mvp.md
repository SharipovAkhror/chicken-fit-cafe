# ADR-004: Архитектура QR-меню MVP

## Контекст

Владелец поручил сделать меню, которое гость открывает по QR-коду со стола: посмотреть
позиции, фото, цену и состав. Заказа, корзины и оплаты быть не должно. Требования
владельца дословно: быстро, легко, всегда работает, бесплатно.

Ограничения на входе:

- обязательные входы `agents/product-developer.md` (approved service blueprint,
  design-system и спецификация) на момент решения не выполнены — см. «Отклонения»;
- меню правит сам владелец, без разработчика;
- гости открывают меню с телефона на мобильном интернете внутри помещения;
- бюджет — ноль.

## Решение

1. **Статический сайт.** Next.js App Router, все страницы меню пререндерятся в HTML
   на сборке (`/`, `/uz`, `/en`). В рантайме нет ни базы, ни API, ни серверной логики:
   гостю отдаётся готовый HTML с CDN. Ломаться в момент сканирования QR нечему.
2. **Источник истины — файл в репозитории.** Всё меню лежит в
   [`content/menu.json`](../content/menu.json). Git даёт бесплатную историю изменений
   и откат любой правки.
3. **Control plane — редактирование этого файла на github.com.** Владелец правит JSON
   через веб-интерфейс с телефона, коммит запускает пересборку Vercel, меню обновляется
   за 40–60 секунд. Отдельная админ-панель не делается (см. «Рассмотренные альтернативы»).
4. **Защита от опечатки.** [`tools/validate-menu.mjs`](../tools/validate-menu.mjs)
   выполняется первым шагом `npm run build` и в CI. Битый JSON, повторяющийся `id`,
   цена строкой, ссылка на несуществующее фото — сборка падает, **на сайте остаётся
   предыдущая рабочая версия меню**. Гость не видит поломки.
5. **Три языка: ru, uz, en.** Русский живёт в корне сайта — это адрес из QR, без
   редиректов. Незаполненные `uz`/`en` откатываются на русский текст: неполный перевод
   не должен блокировать заведение позиции.
6. **Цены — целым числом в сумах** (`45000`). Форматирование и валюта — на стороне кода.
7. **Фото — в [`public/menu/`](../public/menu), до 300 КБ.** Позиция без фото
   показывает плашку с логотипом.
8. **Никаких персональных данных.** Меню не собирает от гостя ничего: ни форм, ни
   авторизации, ни корзины. Единственная сторонняя загрузка — Vercel Analytics,
   уже подключённый в `app/layout.tsx`.

## Рассмотренные альтернативы

| Вариант | Почему не выбран |
| :--- | :--- |
| Внешняя БД (Supabase / Neon) + рантайм-запросы | Лишняя зависимость в критическом пути: упала БД или заснул free-tier — гость видит пустое меню. Мгновенность обновления не стоит этого риска при 2–5 правках в неделю. |
| Админ-панель `/admin`, коммитящая через GitHub API | Удобнее для владельца, но требует хранить токен с правом записи в env Vercel и держать серверный маршрут. Владелец выбрал правку JSON напрямую (решение 2026-08-05). Вернуться к вопросу, если правки станут ежедневными. |
| Google Sheets как источник | Бесплатно, но добавляет внешний сервис, квоты API и ещё один аккаунт в критический путь. |
| Статический HTML без фреймворка | Дешевле, но в репозитории уже есть Next.js, дизайн-токены и shadcn; переписывать с нуля незачем. |

## Последствия

- Обновление меню занимает ~1 минуту вместо мгновенного. Для стоп-листа это приемлемо.
- Правки требуют аккаунта GitHub с доступом к репозиторию.
- Каждая правка меню = коммит в `main`, то есть публичная история цен.
- Рост до десятков позиций и ежедневных правок — сигнал вернуться к вопросу админки.

## Открытые вопросы к владельцу

1. **Домен.** Пока адрес вида `*.vercel.app`. QR печатается один раз, поэтому домен
   лучше решить до печати наклеек.
2. **Vercel Hobby — некоммерческое использование по условиям Vercel.** Меню
   действующего кафе формально коммерческое. Бесплатная альтернатива без этого
   ограничения — Cloudflare Pages. Решение за владельцем; код от хостинга не зависит.
3. **Реальные позиции, цены и фото.** Сейчас в `menu.json` заглушки. Цены — зона
   владельца и финансового аналитика, не агента (`AGENTS.md`, раздел 6).
4. **Генерация QR** — после выбора домена.

## Отклонения от контракта

`agents/product-developer.md` требует approved `operations/service-blueprint.md`,
`design/design-system.md` и `product/specification.md` до начала разработки. Ни одного
из этих документов на 2026-08-05 нет. Работа выполнена по прямому поручению владельца;
спецификация [`product/specification.md`](../product/specification.md) написана вместе
с кодом и остаётся в статусе `draft` до утверждения. Это MVP-меню без заказов и
персональных данных — цена ошибки ограничена содержимым одного JSON-файла.

## Проверка

- `npm run build` проходит; все четыре маршрута помечены как статические.
- `node tools/validate-menu.mjs` ловит битый JSON, дубли `id` и отсутствующие фото.
- Шаг валидации меню добавлен в `.github/workflows/validate.yml`.
- Проверено вручную на 375×812 и 900×1000: раскладка, три языка, стоп-лист,
  карточка блюда, закрытие по Escape.
